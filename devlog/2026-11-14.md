## 1. Chi tiết cập nhật

### 1. Khắc phục triệt để lỗi "Không thể tải dữ liệu thống kê - Phiên đăng nhập không hợp lệ hoặc đã hết hạn"
- **Nguyên nhân gốc rễ:** 
  1. Trong `src/views/Portal.tsx`, tab Tổng quan truyền prop token cho `<AnalyticsDashboard token={bypassToken || null} />`. Tuy nhiên, trong môi trường production Vercel (`ticoolture.vn`), biến môi trường `VITE_ADMIN_TOKEN` không tồn tại, khiến `bypassToken` luôn là chuỗi rỗng `""`.
  2. Bên trong `AnalyticsDashboard.tsx`, hàm `fetchData` chỉ đọc `token` prop và `localStorage.getItem("ti_admin_token")`. Khi cả hai đều rỗng, hàm này tự động gửi header `Authorization: Bearer test_admin_token_local`.
  3. API endpoint `/api/analytics` sử dụng hàm `authenticateStaffMember` để xác thực JWT với Supabase Auth. Chuỗi `test_admin_token_local` không phải là JWT hợp lệ nên Supabase Auth báo lỗi `"Phiên đăng nhập không hợp lệ hoặc đã hết hạn."` (HTTP 401). Kể cả khi Super Admin (`vinhhung3205@gmail.com` hay `locle30092004@gmail.com`) đã đăng nhập Google thành công, token thật vẫn không được chuyển tới API thống kê.
- **Giải pháp xử lý triệt để:**
  - `src/components/admin/AnalyticsDashboard.tsx`: Tích hợp `getSupabaseToken()` trực tiếp từ `src/lib/supabaseClient.ts` để luôn chủ động lấy JWT session thực tế từ Supabase Client (hỗ trợ cả session Google OAuth và bypass token). Bỏ hoàn toàn fallback `test_admin_token_local`. Thêm dependency `[period, token]` vào `useEffect`.
  - `src/views/Portal.tsx`: Quản lý state `sessionToken` từ `supabase.auth.getSession()` và `onAuthStateChange`, truyền `sessionToken || bypassToken || null` vào `AnalyticsDashboard`.
  - `api/_lib/supabaseAuth.ts`: Bổ sung danh sách Super Admin fallback (`locle30092004@gmail.com`, `vinhhung3205@gmail.com`) vào cả `authenticatePortalUser` và `authenticateStaffMember` để đảm bảo tài khoản Super Admin luôn có quyền truy cập quản trị hệ thống và tự động cập nhật vào bảng `staff_members`. Hỗ trợ `process.env.ADMIN_TOKEN` trong production.
  - `api/analytics.ts`: Gia cố xử lý dữ liệu PostgREST trả về (xử lý an toàn khi `shops` là object hoặc array) để tránh crash runtime.

## 2. Rút kinh nghiệm & Sai lầm
- **Không bao giờ hardcode token giả định (`test_admin_token_local`) làm fallback cho API gọi dữ liệu:** Khi client gửi token giả định thay vì báo lỗi thiếu session, backend sẽ cố giải mã JWT và ném lỗi 401 không rõ ràng ("Phiên đăng nhập hết hạn"), khiến việc debug gặp khó khăn vì nhầm lẫn rằng người dùng bị hết phiên, trong khi nguyên nhân thực sự là token chưa từng được truyền vào request.
- **Đồng bộ hóa việc lấy Auth Token qua một hàm tiện ích duy nhất (`getSupabaseToken()`):** Trong SPA kết hợp Supabase Auth, token có thể nằm trong Supabase Client memory/localStorage. Mọi component hoặc view cần gọi API bảo mật phải dùng chung `getSupabaseToken()` bất đối xứng thay vì tự đọc các key localStorage tùy tiện.
