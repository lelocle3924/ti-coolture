**Focus:** Backend Architecture Realignment for 1 Human + AI Agents, Cloudflare R2 Direct Uploads, and Google OAuth Shop Partner Portal.

## 1. What these sessions were about

From Oct 13 to Oct 15, we paused frontend feature exploration to establish the foundational backend architecture of Tí Coolture.

The project operates under a unique, modern operating constraint: **1 human supervisor (Lộc) + LLM coding agents maintaining the platform**. The catalogue is not staying small — mock data of 13 shops will soon be replaced by onboarding real artisan brands across HCMC, scaling up to thousands of high-resolution craft photographs.

This session took the initial drafts (`BE plans.md` and `docs/SRS.md` v1.1) and designed a concrete, production-grade **"Calm Infrastructure"** that will not break under traffic, avoids vendor lock-in traps, and stays completely free of maintenance nightmares.

---

## 2. Key Architectural Decisions Taken

| # | Topic | Decision | Rationale |
|---|---|---|---|
| **D1** | **Repository Structure** | **Single Monorepo** (FE + BE + Migrations) | Keeps a single context for AI agents. When database columns change, TypeScript types across the app update immediately without cross-repo divergence. |
| **D2** | **Image Storage & Delivery** | **Cloudflare R2** with direct client upload | Zero-egress bandwidth fees. AWS S3 or Supabase Storage would rack up bandwidth bills as catalogue views grow. Direct browser PUT bypasses Vercel's 4.5MB payload limit. |
| **D3** | **Shop Authentication** | **Google OAuth (via Supabase Auth)** | Replaced custom magic token links. Artisans in Vietnam use Gmail/Google natively. Zero password storage = 100% compliance with Vietnam Decree 13/2023/NĐ-CP on Personal Data Protection. Reusable for customer accounts later. |
| **D4** | **Access Restriction** | **Hidden Partner Portal** | No links or buttons anywhere on `ticoolture.vn`. Secured via route guard (`noindex, nofollow`) + email whitelist / invitation auto-linking. |
| **D5** | **Content Moderation** | **State-Machine Review Flow** | Products created by shops remain in `draft` or `pending_review`. All public storefront queries strictly filter `WHERE publish_status = 'published'`. Submissions alert Admin via Telegram. |

## 3. What Was Built (Steps 1 – 3)

### Step 1: Database Schema & Migrations (`supabase/migrations/`)
* Fixed 3 structural errors inherited from legacy drafts (corrected audit log actor foreign keys, ordered `shops` before `shop_members`, and added missing `collections` tables).
* Added `portal_invites` and `shop_invitations` tables with auto-linking triggers and Row Level Security (RLS) policies.
* Updated `publish_status` enum to include `pending_review` and `rejected`.
* Consolidated all 13 migrations into a single, clean UTF-8 file: `supabase/full_schema.sql`.
* Synchronized TypeScript types in `src/lib/mock/schema.ts`.

### Step 2: Cloudflare R2 Direct Upload Integration
* Added `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` to `package.json`.
* Built `api/_lib/r2.ts` to generate presigned PUT URLs with Content-Type validation, size caps (12MB), and deterministic key paths (`shops/{shopId}/products/{timestamp}-{hex}.webp`).
* Created client upload helper `src/lib/r2Upload.ts` featuring `XMLHttpRequest` 0–100% progress tracking, image dimension extraction, and concurrency limits (3 parallel uploads).
* Authored detailed setup guide and troubleshooting runbook: `docs/runbooks/R2-SETUP-AND-UPLOAD.md`.

### Step 3: Backend Serverless APIs & Google OAuth Review Flow
* Created Supabase Auth helper `api/_lib/supabaseAuth.ts` supporting session JWT verification and automatic invitation matching (`invited_email` $\rightarrow$ `shop_members`).
* Implemented Vercel Serverless endpoints:
  * `GET /api/portal/me`: Fetches shop profile, role, and current draft products in 1 roundtrip.
  * `POST /api/portal/upload-ticket`: Issues R2 presigned URLs authorized for the caller's specific shop.
  * `POST /api/portal/save-draft`: Saves product details, generates SEO slugs, and syncs drag-and-drop image orders (`product_images`).
  * `POST /api/portal/submit-review`: Locks product editing, transitions status to `pending_review`, and triggers real-time Telegram Bot alerts.
  * `POST /api/admin/portal/invite`: Admin grants shop management access to a partner's Google email.
  * `POST /api/admin/reviews/action`: Admin approves (`published`) or rejects (`rejected`) submissions.
* Built resilient Telegram notification module: `api/_lib/telegram.ts`.
* Updated Backend SRS (`docs/BACKEND-SRS.md`) and wrote `docs/runbooks/GOOGLE-OAUTH-PORTAL.md`.
